# LibrePatch brand files

The logo, icon and colors used on the project's front page and its repository settings.

| File | Use |
|---|---|
| `logo-dark.svg` | Logo for dark backgrounds (white "Libre", mint "Patch"). |
| `logo-light.svg` | Logo for light backgrounds. |
| `icon.svg` | The shield-and-patch icon on its own. |
| `favicon.ico` | Browser icon (16, 32, 48, 64 and 128 px). |
| `social-preview.svg`, `social-preview.png` | The 1280 x 640 image shown when the repository is shared. Upload the PNG under **Settings > General > Social preview** (GitHub takes PNG, JPG or GIF, not SVG). |
| `how-it-works.svg` | The diagram on the front page. |

## Colors

| Name | Hex | Where |
|---|---|---|
| Teal | `#0F766E` (light backgrounds), `#14A394` (dark backgrounds) | The shield |
| Amber | `#F5A524` | The patch; accents for "needs attention" |
| Mint | `#5EEAD4` | "Patch" in the dark-background logo; highlights |
| Deep green | `#0B1F1D` | Dark backgrounds |
| Off-white | `#F4F7F6` | "Libre" in the dark-background logo; text on dark |
| Ink | `#0B3B37` | The arrow on the patch |

## Using the logo

The AGPL covers the code, not the name or the logos. See [TRADEMARKS.md](../../TRADEMARKS.md): you may say your product is
"based on" or "compatible with" LibrePatch, but a fork should use its own name and branding. The console lets an organization
set its own name, logos and colors (Settings > Branding), so a deployment never has to show this logo.
