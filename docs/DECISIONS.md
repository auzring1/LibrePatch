| D51 | Large uploads (up to 2 GiB) are a single streamed `application/octet-stream` request to `/api/v1/catalog/content`; Caddy raises its body limit for that one path only (1 MB elsewhere) and the handler extends its own deadlines | Keeps the JSON API's small default limits for every other endpoint |
| D52 | The VM test matrix is a **harness plus an empty results file** (`test/vm-matrix`, `matrix_results.json`); nothing is "verified" until a human runs it on real VMs and commits the results | Claiming verification that did not happen would defeat the flag |
| D53 | An **update** removes older copies the new installer will not replace in place, and does it **before** installing: `Remove old X` jobs (one per older machine-wide row, chained) then the update, each linked with `depends_when = finished`. A copy counts as replaced in place when the new installer's detection rules name the same Uninstall key | Found in testing: updating a 7-Zip EXE install to the MSI left two copies. | D54 | Cleanup uninstalls carry `remove_older_than`: the **agent** re-reads the row's `DisplayVersion` and only removes it if strictly older (unknown or equal versions are left alone; a row that is already gone is success) | The server planned from a possibly stale inventory, and an in-place upgrade may have reused the key; the agent must never remove the version that was just installed |
| D55 | Only **revoked or retired** devices can be deleted (`DELETE /devices/{id}`, bulk `POST /devices/delete`). | D56 | **Refresh** is an `INVENTORY_FULL` job (reused if one was requested in the last 2 minutes; only for online devices) that makes the agent send software and users, hardware if changed, and a heartbeat (uptime, reboot state, signed-in user) immediately | Same signed-job path as everything else: audited, subject to the agent's policy ceiling, visible on the Jobs tab. | D57 | **Uninstall from inventory** creates ad-hoc jobs with no deployment and no catalog package; system components, AppX and portable rows are refused. **Missing updates** are computed from installed programs matched to imported catalog packages by normalized name and the package's effective (pinned) newest version; self-updating apps are listed as "vendor updates" and not deployable | Matches how administrators use the device page without forcing every program into the catalog. | D58 | The Windows Update snapshot is a **full-replacement `WU` inventory section** with a generation counter (not a delta, not a timestamp), resynced through the existing `Hello.revs`/`ResyncRequest` mechanism | Update lists are small (only what is missing) and change wholesale on a scan; a delta would add complexity for no saving. | D59 | Approvals are keyed by **update identity (not revision)**; "pending" is the absence of a row; rules act only on pending updates and never overwrite a manual decision; the device installs whatever revision a fresh scan finds | Microsoft revises updates under the same identity and the agent must install what WUA offers now. | D60 | **Rings** are ordered by `ordinal`; a device belongs to the first ring whose groups contain it; devices in no ring are never auto-updated. A ring opens when the previous one has soaked and ≥ half its devices have reported (or a week after the soak); a failure rate above `100 − success_threshold` raises a **hold** immediately; releasing a hold counts as a pass; a ring with nothing to do does not block the next one | One unambiguous membership rule; failing fast on bad updates matters more than waiting for the soak; administrators keep the final say through the release action |
| D61 | Scheduler limits: ≤ 500 jobs/tick, ≤ 50 updates/job, 7-day job lifetime, ≤ 3 automatic failures per (device, update) with ≥ 24 h between tries; scheduled install jobs retry transient errors twice with a 5-minute backoff on the device (manual installs once) | Bounds the blast radius of a bad rollout and of a server bug, and prevents a permanently failing update from being re-attempted forever |
| D62 | The update **source** (default/WSUS, Windows Update, Microsoft Update; include drivers) is an organization setting delivered to devices as a `WU_SCAN` job; the agent stores it and **scans on its own every 24 h** (and after a restart), so inventory stays fresh without server round trips | Keeps the server stateless about schedules and works for devices that were offline when the setting changed |
| D63 | Restarts use the **system shutdown countdown** (`InitiateSystemShutdownEx`, signed-in users see it, an administrator can abort) instead of a custom session notifier; install jobs can request `never`, `outside_active_hours` or `deadline` only; `REBOOT_ALLOW_NOW` exists solely for the explicit `REBOOT` job with ≥ 1 minute countdown and an online device | The built-in countdown works for every session without a helper or UI of ours and cannot be spoofed by a user process; refusing "now" in install jobs removes the main way a policy could reboot machines unexpectedly |
| D64 | **Conflicting update management** (WSUS, WUfB deferrals, configure-automatic-updates, disabled service) is **detected and reported, never changed** | Changing those policies is an administrator's and Group Policy's job; silently overriding them would fight the customer's own control plane |
| D65 | RBAC adds `updates:read` (all roles), `updates:write` (admin, operator) and `updates:policy` (admin only) | Operators can approve and push updates; changing the rollout policy itself, source settings and releasing a failed ring's hold are administrative acts |
| D67 | The agent **MSI** (WiX **7.0.0**, pinned in `.config/dotnet-tools.json`; EULA acceptance passed explicitly as `--acceptEula wix7` in the build scripts) is a thin wrapper: it stages `librepatch-agent.exe` in `%ProgramFiles%\LibrePatchSetup\` (deliberately **outside** `LibrePatch\Agent`, which `uninstall` deletes) and runs `install --if-not-installed ...` / `uninstall` from deferred, SYSTEM-context `WixSilentExec64` actions (no cmd.exe, no PowerShell, no scripts; the command line and output are not logged). Public properties are only `SERVER`, `TOKEN` (hidden), `ALLOWEDJOBS`, checked by launch-condition deny lists and again by the agent. A failed fresh install rolls back with `uninstall`; a major upgrade skips the old package's uninstall and never re-enrolls (`--if-not-installed`). x64 only, Windows 10 1809+ / Server 2019+ | The agent binary stays the single installer (O6), so GPO/Intune/RMM get a standard package without a second install path. WixSilentExec is used instead of an exe custom action because an exe action's command line (with the token) would be written to verbose MSI logs. | D66 | **Backup is an age-encrypted tar stream** (`librepatch-server backup` / `restore`, `internal/server/backup`): `header.json` first (versions, tables in foreign-key order with their columns, sequences), COPY text chunks of ≤ 8 MiB per table, the content directory as `files/…`, and `manifest.json` **last** (row counts, SHA-256 and size of every other member). Scope: every table in `public` found from the catalog (partitioned parents, not partitions; generated columns excluded; goose's table only as the schema version), sequence positions, content files. **Not** the master key or `deploy/secrets/`, the Postgres roles, `.env` or Caddy state. Encryption is age with public-key recipients (repeatable) or an scrypt passphrase from a file, never plaintext and never a passphrase on argv. Snapshot is one `REPEATABLE READ READ ONLY` transaction. Restore needs an empty database (`--force --wipe` to replace), builds the schema with the embedded migrations up to the backup's version (`goose.UpTo`), loads in one transaction with triggers off, verifies all hashes before COMMIT (and the whole file first when it is seekable), refuses newer-schema or unknown-format backups, then migrates forward and verifies the audit chain. Format version 1; no compression; `filippo.io/age` (BSD-3-Clause) is the only new dependency | A single self-contained file that restores into a newer release; streaming (the manifest is last because hashes are only known after the data, the header is first so the schema can be built before any data arrives); catalog-driven so a new migration needs no backup code change; the KEK stays out so one stolen backup does not carry the keys that unseal it; age is small, audited, permissively licensed and supports offline recipient keys, which suits unattended backups. | D68 | **Agent releases are trusted through a vendor Ed25519 key compiled into the agent**, not through the customer's server. | D69 | **A/B slots with a rollback task run by the *old* binary**; the new version proves itself by completing a handshake; the window is 10 minutes (`update_rollback_minutes` 1–60 in the agent config for tests); a restart is a deliberate non-zero service exit (the recovery option "also on non-crash failures" is set at install and at each switch); no switch happens unless the task could be armed | A broken new binary cannot undo itself, so the safety net must not depend on it. | D70 | **Rollout:** one target release per organization with optional pilot groups, soak time, success threshold, per-minute batch size and window. | D72 | **API tokens:** `lp_` + 256 random bits, only the SHA-256 stored, shown once; mandatory expiry ≤ 365 days; scopes ⊆ the creator's permissions at creation and ∩ the owner's *current* permissions at use; no `users:*` scope; a token cannot create tokens or manage security keys; a disabled owner disables the token; bearer requests skip the Origin check only when no session cookie is present; audit entries made through a token say so (`via_api_token`) | Automation without a long-lived all-powerful credential; demoting a person immediately weakens their tokens |
| D73 | **Security keys (WebAuthn, go-webauthn) are a second factor, not a passwordless login.** A user always keeps at least one factor (authenticator app or key); recovery codes and the administrator's "reset second factor" still exist; ceremony state lives in the database (5 minutes, single use) | Adds phishing-resistant MFA without changing the sign-in model.
